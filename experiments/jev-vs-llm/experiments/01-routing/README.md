# 01 — Routing / Fixed Intent Classification

## Question

For a bounded decision with many allowed labels, how do Jev and an LLM compare on **correctness, end-to-end latency, and cost**?

## What "Routing" Means

In this benchmark, **routing does not mean technical network routing or packet forwarding**. Instead, it refers to **semantic intent routing** in enterprise customer support:

```text
Customer Support Message
            ↓
Classifier / Decision Engine (JEV or LLM)
            ↓
1 of 77 Predefined Intent Destinations
```

Concrete examples from the dataset:

```text
"I haven't received my new card yet"
        ↓
card_arrival

"I was charged twice for the same transaction"
        ↓
card_payment_fee_charged / wrong_amount_of_cash_received

"I forgot my PIN number"
        ↓
pin_blocked / change_pin
```

## Why BANKING77 is a Rigorous Benchmark for Jev vs LLMs

This is not a toy 3-class problem (e.g., `billing`, `support`, `other`). BANKING77 (*Casanueva et al., PolyAI 2020*) presents:

1. **77 fine-grained classes with high semantic overlap**: Numerous categories address closely related banking actions (card delivery, card activation, pin reset, fee disputes, foreign exchange). The system cannot rely on superficial keyword matching.
2. **Realistic bounded decision space**: High-volume customer support automation requires reliably directing queries to exact structured business actions.
3. **Dedicated Decision Engine vs Autoregressive Token Generation**: Jev exposes a native probability distribution across discrete candidate choices (`Choice`), whereas an LLM must ingest all 77 descriptions in-context and generate structured JSON, testing schema compliance, reasoning latency, and token consumption.
4. **Latency and cost sensitivity**: In high-throughput ticket triage, sub-100ms decisions with minimal computational overhead are essential.

## Evaluation Architecture

```text
                    BANKING77
                         │
                         ▼
           "Customer message string"
                         │
          ┌──────────────┴──────────────┐
          │                             │
         JEV                           LLM
          │                             │
          ▼                             ▼
   predicted_intent              predicted_intent
          │                             │
          └──────────────┬──────────────┘
                         ▼
             Official Ground Truth
```

- **Dataset**: BANKING77 official test split (3,080 human-annotated examples, 77 intents, ~40 examples/intent).
- **Zero synthetic ground truth**: All labels come directly from PolyAI's original human annotations; no labels are generated by GPT or Jev.
- **Decision space**: 77 supported banking intents.
- **Jev**: One `Choice` evaluated over the candidate labels.
- **LLM**: Strict Structured Output JSON containing only `chosen_intent`, native confidence, and selected-class probability.
- **Fair latency comparison**: The LLM is deliberately **not** asked to generate all 77 class probabilities token-by-token, as that would unfairly distort the latency comparison.

## Key Distinction: Routing vs Calibration

- **Routing (`01-routing`) is Closed-Set Classification:**
  The model is told that the query **definitely belongs to one of the 77 banking categories**:
  *“Which of the 77 doors is the right door?”*
- **Calibration (`02-calibration`) is Open-Set / Out-Of-Scope Detection:**
  The model receives both in-scope queries and out-of-scope queries (from CLINC150) mapped to `other`:
  *“Is the right door among these 77, or is none of the doors the right one?”*

## Primary Metrics

- **Accuracy** with 95% Wilson confidence intervals;
- **Macro-F1** across all 77 classes (unweighted average to prevent majority class bias);
- **Valid-output rate** (strict adherence to JSON schema);
- **Latency** (client-observed p50 / p95 / p99);
- **Top confusion pairs** (identifying semantically adjacent misclassifications).

## Profiles

The benchmark provides four cost/coverage tiers with **deterministic, class-balanced sampling** (seed=42):

| Profile | Total Cases | Cases / Class | Description |
|---|---:|---:|---|
| `budget` | 77 | 1 | Fast, low-cost smoke validation across all 77 intents |
| `quick` | 154 | 2 | Integration check and rapid regression test |
| `standard` | 770 | 10 | Default statistically meaningful comparison |
| `full` | 3,080 | ~40 (all) | Full official test set for high-coverage benchmarking |

## How to Interpret Results

When examining the dashboard or HTML reports:
1. **Accuracy vs Latency**: A latency advantage for Jev or a compact model is only valuable if accuracy remains competitive on the 77 classes.
2. **Top Confusion Pairs**: Inspect whether errors are sensible (e.g. `card_arrival` vs `card_delivery_estimate`) or catastrophic out-of-family mistakes.
3. **Macro-F1**: Confirms that performance is uniform across all 77 classes, not just skewed towards easier intents.
